I cannot draw. Sprite-acus is how there are sprites.

The workflow is: generate a character however you like — I use AI — then hand
the render to Sprite-acus, and what comes back is an animated pixel art sprite
a game engine will actually take.

Generating the picture is the easy half. The half that used to eat an evening
is everything after it: slicing the page into frames on an exact grid rather
than a guessed one, cropping and scaling each figure the same way, pulling
every colour onto the project's palette, and writing it all out indexed, with
the kind of transparency an engine expects rather than the kind an image editor
produces.

## What you get back

<Split src="/projects/sprite-acus-a.webp" side="right">

For one page — one character, one action, one direction — you get numbered PNG
frames, a contact sheet to actually look at, an editable Aseprite file to do
the cleanup in, and a report recording every input and output.

It works with or without a master palette. Given one, every sprite is pulled
onto it, which is what a project with locked colours needs and what this was
built for. Given none, it takes the colours from the page itself and lets you
say how many.

</Split>

## Where it honestly is

Super alpha. It works, and it is what the sprites in
[Shepherds We Shall Be](/projects/shepherds-we-shall-be/) are made with, so it
is doing real work rather than sitting in a repo being a good idea.

But it still hands you something that needs a pass in Aseprite before it is
finished — that is what the editable file is for. Closing that gap, so a
generated image comes out done rather than nearly done, is what is being built
next. Until then, "a click or two" is the goal rather than the current state,
and it would be dishonest to describe it any other way.

## What it will not do

It does not generate the source image. That is on you and whatever you generate
with — Sprite-acus starts where that finishes.

<Split src="/projects/sprite-acus-b.webp" side="left">

It also will not clean pixel clusters, make artistic decisions, produce the
final authoritative master, or import anything into an engine. A successful
conversion means mechanically valid, never artistically approved.

That distinction is deliberate rather than a shortfall. A tool that quietly
decided which pixels an artist meant would be worse than one that hands over a
scaffold and gets out of the way.

</Split>
