Twenty-four exercises from The Odin Project, kept in one repository rather
than scattered across twenty-four of them. Almost every one is deployed, so
they can be used rather than just read.

## What the progression actually shows

The interesting part isn't any single exercise. It's the line they draw.

<Split src="/projects/odin-projects-a.webp" side="left">

The early ones are layout. **Odin Recipes** is structural HTML and nothing
else. The **Admin Dashboard** is CSS Grid pushed until it stops being
comfortable, and the **Landing Page** is the same exercise for Flexbox.
Nothing moves. The page is what you wrote.

</Split>

Then the DOM starts doing the work. **Etch-A-Sketch** builds its own grid at
runtime and rebuilds it whenever the size changes, which is the first point
where the markup you write and the markup that exists stop being the same
thing. **Coolculator** is where it gets awkward — a calculator looks trivial
until you try to chain operations, and then the edge cases outnumber the happy
path.

**Tic-Tac-Toe**, **The Ark** and **KOI** separate state from rendering
properly: the board lives in JavaScript and gets drawn, rather than the page
being read back to find out whose turn it is. KOI generates its entire page
from modules with no static markup at all.

## Where it stops being exercises

**Testing Practice** is 58 tests over five functions, verified by deliberately
breaking the code to check the tests actually catch it — which is the only way
to know a green suite means anything. **Battleship** was then written
test-first, against an AI that hunts rather than guesses.

<Split src="/projects/odin-projects-b.webp" side="right">

Then the computer science: **linked lists**, a **hash map** with linked-list
buckets and a page to watch it grow, a balanced **binary search tree** raced
against a degenerate one holding the same values, and **Knight's Travails**
solved breadth-first.

Racing the balanced tree against the unbalanced one is the good bit. It is one
thing to be told what happens when a BST degenerates and another to watch the
same values take an order of magnitude longer.

</Split>

**React** arrives with a CV builder that previews live and prints clean, a
memory game that reshuffles on every pick, and a shop with Router, Context and
46 tests.

And then it leaves the browser. **portfolio=#** is this portfolio as an actual
SQLite database you query from a terminal. **A server, by hand** is four pages
on Node's raw `http` module — no Express, no dependencies, just the thing
underneath the thing everyone uses.

That is the arc: from writing what the browser shows, to writing the thing that
decides what the browser shows, to writing the thing the browser is talking to.
